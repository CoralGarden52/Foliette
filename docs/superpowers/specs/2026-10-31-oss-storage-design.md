# Foliette 接入阿里云 OSS

## 已确认需求
用户已完成 Bucket 创建并要求连接：`foliette-photos-prod`，华南1（深圳），公网 Endpoint `oss-cn-shenzhen.aliyuncs.com`；正式网站部署在腾讯云。会话已选定服务端访问私有 Bucket，不更改照片的用户隔离和前端编辑/导出方式。

## 设计
- 继续使用同源 `/api/files/:userId/:name`：Express 验证登录和文件所属用户后，从本地或 OSS 流式返回。浏览器不接触 AccessKey，不需要 OSS CORS；图片仍通过网站服务器传输，会同时使用云间流量与网站服务器带宽。
- 服务器使用 `ali-oss` 6.x、HTTPS、V4 签名和仅授权目标 Bucket `photos/*` 的 RAM 用户凭证。源代码和浏览器不包含真实凭证，错误响应不泄露 SDK 请求参数。
- `PHOTO_STORAGE=local|oss`，默认 local。OSS 模式缺少凭证时明确拒绝启动，不悄悄改存本地。每条上传记录增加 storage/object_key/mime_type，旧记录默认 local，避免新上传改 OSS 后旧图片消失。
- 上传仍先在本地暂存并校验文件签名。整批上传完成后一次提交记录；失败时不提交半批数据，清理暂存及已尝试的远端对象。成功后删除 OSS 上传的暂存文件。
- 数据库持久化删除队列。用户删除照片或作品时，在事务中撤销元数据并排队，异步清理物理文件；网络失败保留队列，启动及每分钟重试。无元数据的旧文件只允许对应账号读取本地兼容路径；删除前为旧文件建清理标记，避免排队期间仍被读取。
- 保存作品只允许引用同一用户且同一作品的上传记录，或真实存在的旧版本本地文件；不接受任意 OSS URL。远端读取返回404与503有明确区分。
- 保留本地文件和当前用户端运行。提供用户 Bucket 已填好的 `.env.oss.example`，以及 `start:oss`、`oss:check`。检查命令只创建随机测试对象并校验读回再删除，不读用户照片。
- 提供可重复执行的本地照片复制迁移命令，默认 dry-run；`--apply` 才上传，确认远端大小后更新记录，保留本地原件，不自动迁移实际用户数据。

## 验证
使用临时数据库和可控 OSS 客户端做存储和 HTTP 集成测试，覆盖旧记录升级、远端错误、私有鉴权、跨作品引用、上传回滚、删除重试、配置缺失与凭证不泄露。再跑现有测试、类型检查、构建。真实云连接因用户尚未配置凭证而待验证，不能宣称已连通 Bucket。
